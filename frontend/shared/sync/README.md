# Модуль sync

Изменено: 02.06.2026

`sync` отвечает за доставку локальных изменений на сервер и за применение изменений, пришедших с сервера обратно в локальную базу.

Если коротко, то именно этот модуль делает приложение пригодным для работы без сети.

## Структура

```text
sync/
├── data/
└── domain/
```

## Основные классы

Контракт синхронизации задают:

- `SyncRepository`
- `SyncManager`

`SyncManager` умеет запускать синхронизацию через `requestSync()` и `forceSync(retry)`.

Текущее состояние доступно через `StateFlow<SyncStatus>`.

Возможные статусы:

- `Ok`
- `InProcess`
- `Failed`
- `WouldRetry(inSeconds)`

## Реализация

Основная логика находится в:

- `SyncManagerImpl`
- `SyncRepositoryImpl`
- `SyncQueueRepositoryImpl`
- `SyncQueue`

Менеджер работает через очередь операций. Остальные модули сохраняют изменения локально, а `sync` постепенно отправляет их на сервер и применяет ответ обратно в локальное хранилище.

Подробнее устройство синхронизации описано в `docs/architecture/synchronization.md`.
