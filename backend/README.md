# Backend

Изменено: 02.06.2026

Backend отвечает за API, авторизацию, синхронизацию и хранение серверного состояния в PostgreSQL.

Код построен вокруг FastAPI, SQLAlchemy, Alembic и слоя сервисов. Доступ к базе должен идти через репозитории и Unit of Work, а не напрямую из роутов.

## Структура

```text
backend/
├── alembic.ini
├── pyproject.toml
├── uv.lock
└── src/
    ├── api/           # FastAPI роуты
    ├── core/          # конфигурация, безопасность, общие настройки
    ├── database/      # подключение к базе и session factory
    ├── dependencies/  # зависимости FastAPI
    ├── migrations/    # Alembic migrations
    ├── models/        # SQLAlchemy модели
    ├── repositories/  # доступ к данным
    ├── schemas/       # Pydantic-схемы и DTO
    └── services/      # бизнес-логика
```

## Слои

### api

Здесь находятся роуты FastAPI. Роут должен принять запрос, получить зависимости и передать работу в сервис.

### services

Сервисы содержат бизнес-логику. Например, авторизация и синхронизация реализуются именно здесь.

Сервис не должен вручную управлять SQLAlchemy session. Для работы с базой используется `UnitOfWork`.

### repositories

Репозитории отвечают за доступ к данным.

Для типовых операций уже есть `GenericRepository`: получение по id, выборки, создание, обновление и удаление не нужно каждый раз писать заново.

### models

SQLAlchemy-модели базы данных:

- счета;
- категории;
- операции;
- пользователи;
- email-коды;
- операции синхронизации.

### schemas

Pydantic-схемы для входных и выходных данных.

Здесь же лежит общий `Result`, который используется сервисами для возврата результата операции.

### migrations

Alembic-миграции. Если меняется SQLAlchemy-модель, нужна новая миграция.

## Команды

Команды запускаются из корня проекта.

Создать новую миграцию:

```bash
make revision m="сообщение_миграции"
```

Применить миграции:

```bash
make upgrade
```

Запустить backend:

```bash
make run
```

## Как добавлять новую сущность

1. Создать SQLAlchemy-модель в `src/models`.
2. Добавить модель в `src/models/__init__.py`.
3. Создать репозиторий в `src/repositories`.
4. Если хватает стандартных CRUD-операций, наследоваться от `GenericRepository`.
5. Добавить сервис в `src/services`.
6. Добавить схемы в `src/schemas`.
7. Подключить роут в `src/api`, если нужен внешний API.
8. Создать Alembic-миграцию.

## Правила для backend-кода

- Роуты не должны работать с базой напрямую.
- Сервисы должны использовать `UnitOfWork`.
- Репозитории должны инкапсулировать SQLAlchemy-запросы.
- Новые изменения схемы базы должны сопровождаться миграцией.
- Если в проекте уже используется `Result`, новый сервисный код лучше писать в том же стиле.
