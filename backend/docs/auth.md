# Авторизация

Изменено: 02.06.2026

Основная логика авторизации находится в `AuthService`.

## Регистрация

Во время регистрации:

```text
register
  -> create user
  -> generate OTP
  -> save email code
  -> return code
```

Если пользователь уже существует и подтверждён, возвращается ошибка.

Если пользователь существует, но ещё не подтверждён, сервис может повторно использовать существующую запись.

## Отправка email через SMTP

После регистрации или повторного запроса кода `AuthService` генерирует OTP-код и сохраняет в базе только его хэш.

Обычный код используется для письма пользователю. Отправка выполняется через SMTP-слой проекта, а авторизация остаётся ответственной только за создание и проверку кода.

Такой подход разделяет две задачи:

- `AuthService` создаёт и проверяет код;
- SMTP-слой доставляет письмо пользователю.

С точки зрения безопасности код подтверждения не хранится в открытом виде. В базе сохраняется только хэш, а plain text значение используется только во время отправки письма.

## Подтверждение регистрации

`verify_register(...)`:

1. получает пользователя;
2. получает код подтверждения;
3. проверяет срок жизни кода;
4. сравнивает хэш кода;
5. помечает пользователя как подтверждённого.

После успешной проверки код удаляется.

## Повторная отправка кода

`resend_verification_code(...)` создаёт новый код только если старый уже отсутствует или истёк.

## Вход

Во время логина сервис:

1. ищет пользователя по email;
2. проверяет подтверждение регистрации;
3. проверяет пароль;
4. создаёт access и refresh токены.

Создание токенов выполняется через `security.Token.create_token(...)`.
